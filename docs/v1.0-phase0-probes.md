# v1.0 Phase 0：两个探针的结论

阶段 0 的出口是结论，不是代码。两个探针做完才允许动 A/B/C/D 的代码，否则整套东西都建在猜测上。
完整记录（含命中计数与可复现脚本）在 `<工作台>/checks/2026-11-06-phase0-probes.md`。

## 探针 1：面板能否拿到 sessionId 并注入当前会话 → **能**

- 内置右栏 tab 的标准注册就是
  `ctx.slots.inject("sidebar.right.pane.tab", () => ctx.slots.register({ name, key, locale }, Body))`，
  而 `ctx.sidebarRightTabs` 负责列举/开关（证据：`dsh-client-ui-plan`、`dsh-client-ui-chat` 的 client bundle）。
- 宿主注入原语 `sessionController.prompt({sessionId, requestId, mode:'queue', content}, signal)`
  是"排进这条会话的下一轮"，不是新建会话。

结论：tab body 自带 `sessionId`，短活由宿主排队注入当前会话；长活才派生子会话。
残留：自定义 pane 是否真的收到 `sessionId` 需一次真实挂载（重启清单第 1、2 条）。

## 探针 2：生图能不能在 v1.0 真跑 → **不能，且不该假装能**

- `generateImages` 在 `app.asar` 里有 40 处，全在 `@earendil-works/pi-ai`、`@google/genai` 与 pdfjs；
  收紧到 DSH 自有包只剩 pdfjs 的注释栅格化器，llm/session 包 **0 处**。
- pi-ai 的 `images-api-registry` 被 DSH 引用 **0 次**；`/images/generations` 只出现在捆绑的 `openai` 客户端。
- 插件面的 `llm` 服务 = chat（`listProviders / listModels / stream`），图像只作为**输入**。

结论：画布上的 `llm / image / video` 三种 executor 在 v1.0 **故意不注册**——节点灰显、拒绝运行、
不写假产物。接桥是 E 阶段的独立决策（直连 openai 兼容网关 / ComfyUI MCP / 第三方 API），需要真实凭据与一次
带凭据的探测。
